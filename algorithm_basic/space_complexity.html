공간 복잡도 Big-O Notation

O(1) 상수 공간

O(log n) 로그 공간

O(n) 선형 공간

O(n log n) 선형 로그 공간

O(n²) 이차 공간

O(2ⁿ) 지수 공간

시간 복잡도와 마찬가지로 공간 복잡도도 상수 시간을 무시하고 가장 높은 차수를 기준으로 빅오 표기법(Big-O Notation)을 사용하여 나타낸다. 공간 복잡도에서 상수는 입력값의 크기와 상관없이 항상 고정된 크기를 차지하는 변수나 배열을 의미한다. 고정된 크기(상수)는 무시하고, 데이터 크기에 비례하여 동적으로 늘어나는 메모리 공간만 측정하여 O(n)으로 표기한다. 만약 변수만 100개 사용하고 배열을 아예 안 쓴다면 공간 복잡도는 그냥 O(1)이 된다.

공간 복잡도의 구성 요소

공간 복잡도란, 알고리즘을 실행하고 완료하는 데 필요한 총 저장 공간량을 의미한다. 입력 크기에 따라 필요한 메모리의 양을 측정하는 것이다. 공간 복잡도는 크게 고정 공간, 가변 공간으로 나눤다. 고정 공간은 입력 크기와 상관없이 항상 일정하게 유지되는 공간이다 단순 변수, 상수 등이 포함된다. 가변 공간은 문제를 해결하기 이해 알고리즘이 실행되는 동안 동적으로 필요로 하는 공간이다.

공간 복잡도 표기법 이해

O(1) : 입력 크기 n과 관계없이 항상 일정한 크기의 메모리를 사용하는 경우 (예: 단순 변수 몇 개만 쓰는 반복문)

# 변수 몇 개만 사용하는 경우
def get_sum(numbers):
    total = 0

    for num in numbers:
        total += num

    return total

입력 크기에 비례해서 추가 메모리가 증가하지 않으므로 O(1)이다.

O(n) : 입력 크기 n에 비례하여 메모리를 차지하는 경우 (예: 크기가 n인 1차원 배열 생성)

def double_numbers(numbers):
    result = []
    for num in numbers:
        result.append(num * 2)

    return result

이 코드는 입력 원소마다 새로운 원소를 하나씩 저장한다.
입력 크기가 10배가 된다면 리스트 원소 수도 10배가 된다. 입력 크기의 제곱에 비례하여 메모리를 차지하는 경우는 O(n²)가 된다.
중요한 점은 원소를 반복해서 처리한다고 무조건 O(n)의 공간 복잡도가 되는 것은 아니다. 반복문 자체가 아니라 그 과정에서 얼마만큼의 데이터를 메모리에 보관하는 지가 중요하다.

코딩 테스트에서 공간 복잡도 활용

일반적인 코딩테스트에서는 시간 복잡도가 공간 복잡도보다 더 자주 중요한 판단 기준이 된다. 그렇다고 공간 복잡도를 무시해도 되는 것은 아니다. 공간 복잡도는 메모리 제한을 판단하고 비효율적인 자료구조 사용을 피하기 위한 중요한 판단 기준이 되고, 문제에서 메모리 최적화가 핵심 조건으로 등장할 수도 있다. 코딩테스트에서는 보통 다음 세 가지 상황에서 공간 복잡도를 고려한다.

① 입력 데이터의 크기에 따라 자료구조를 선택할 때

예를 들어 문제에서 정수 100만 개가 주어지고 중복을 제거해야한다고 가정해보자.
방법 A는 새로운 리스트를 만들고, 방법 B는 집합(set)을 사용한다. 

# 방법 A: 새로운 리스트에 중복없이 저장
result = []
    
for num in numbers:
    if num not in result
        result.append(num)
# 방법 B: set 사용
result = set(numbers)

두 방법 모두 데이터가 많으면 추가 메모리를 사용할 수 있다. 하지만 첫번째 방법은 매번 리스트를 탐색하므로 시간복잡도도 불리하다. 반면 두번째 방법은 해시 기반 자료구조를 사용하여 훨씬 효율적으로 중복을 제거할 수 있다.
공간 복잡도를 따질 때는 메모리를 사용해 시간을 얼마나 절약할 수 있는지도 함께 판단해야한다.

② 메모리 제한을 넘지 않는지 판단할 때

입력 크기가 n일 때, 메모리를 추가로 n개만 사용하는 알고리즘과 n²개 사용하는 알고리즘은 차이가 매우 크다. 문제를 풀 때, 코드 작성 전에 다음을 한번 따져보자
입력 크기가 최대 얼마인가?
추가 리스트나 딕셔너리가 입력 크기에 비례해서 늘어나는가?
2차원 배열을 만들면 메모리가 감당 가능한가?
재귀 호출이 너무 깊어지지는 않는가?

③ 시간을 아끼기 위해 메모리를 더 사용할지 판단할 때

어떤 값이 이미 등장했는 지 확인하는 문제를 예시로 들어보자
리스트 검색 : 추가 메모리를 거의 쓰지 않을 수 있지만, 검색에 O(n)이 걸릴 수 있음
집합 사용 : O(n)의 추가 공간을 쓰지만, 원소 검색은 평균적으로 O(1)
이런 경우에는 메모리를 더 사용하는 대신 실행 시간을 줄이는 선택을 할 수 있다. 이를 시간-공간 트레이드오프(time-space trade-off) 라고 한다. 모든 문제에서 공간 복잡도가 낮은 알고리즘이 더 좋은 것은 아니다. 주어진 시간 제한과 메모리 제한 안에 적절한 균형을 찾는 것이 핵심이다.

코딩 테스트에서 공간 복잡조는 입력 데이터가 매우 큰 문제, BFS·DFS·DP 문제에서 중요도가 높다. 코드를 작성하며 입력이 100만 개라면 메모리가 감당될까? 리스트나 딕셔너리를 불필요하게 여러 개 만들고 있지 않을까? 2차원 배열을 만들지 않고 해결할 방법이 있을까? 등의 질문을 하며 공부하면 도움이 된다.
